# 爆片分析

团队内部使用的 TikTok 带货视频多模态拆解工具。支持 TikTok 链接和本地视频，输出中文分析并按产品长期归档。

当前生产主链路是飞书手卡与多维表格自动化，数据存储使用 MySQL。历史网页、机器人和旧商品链接解析代码仍保留，不代表它们都是当前业务入口。本分支已停用旧商品链接分析接口，部署后生效。最近一次可靠性审计、已修问题及未验证边界见 [可靠性审计](deploy/RELIABILITY_AUDIT_20260930.md)。

## 已实现

- 产品档案：图片、品类、市场、售价、卖点、目标用户、痛点、竞品、合规词和备注
- 分析页面可快速新增产品，只需名称、类目和选填 PID，创建后自动选中
- 最多 10 条 TikTok 链接或本地视频批量排队
- 队列任务可随时停止，正在进行的模型请求会被中断且不会自动恢复
- 英语、西语原文识别及中文翻译
- 自动分镜和逐镜头画面/声音分析
- 清晰度、美感、光线、产品主体、流量、转化、声音和节奏评分
- 钩子、爆点、卖点、信任点、CTA 标记
- 爆点截图与 3–10 秒关键片段
- AI 仿写口播和复拍分镜
- 两条视频对比
- 按产品、账号、日期和文案搜索
- 团队人工标记“优质 / 普通 / 较差”，用于同产品后续分析参考
- 长期学习系统：每条完整报告会沉淀为视频经验，按产品、品类和全局三层整合
- 新视频自动检索相似历史案例；人工标签和备注拥有最高学习权重
- 学习中心可查看已学习数量、可信度、有效钩子、胜出结构和常见风险
- 原视频、封面、截图、片段和报告长期保存在本机
- 已完成、失败或已停止的视频可二次确认后永久删除，并同步清理全部本地媒体
- 飞书双向机器人：单聊直接发送，群聊必须 @机器人，支持自然表达的“产品名称 + 选填 PID + 最多 10 条 TikTok 链接”
- 飞书机器人实时更新排队、下载、识别、分镜、分析和报告生成进度；重复链接可以创建独立任务，不按 URL 全局复用分析
- 完成后返回含六维评分的飞书卡片和完整飞书文档，文档包含原文案、中文翻译、逐镜头分析、截图和爆点片段
- 卡片可直接标记优质/普通/较差或重新分析，并同步进入本地长期学习系统
- 网页中的已完成报告可选择最近使用的人或群聊，一键发送到飞书

## 第一次使用

1. 先阅读 [隔离验收说明](deploy/ISOLATED_ACCEPTANCE.md) 和 [模型设置说明](deploy/AI_SETTINGS.md)。仓库的 Compose 文件指向现有生产卷，不可直接用作本地测试环境。
2. 开发需要 Node.js、pnpm 和隔离 MySQL；版本以 `Dockerfile` 与 `package.json` 为准。
3. 服务商密钥通过受保护的后台录入；后台登录配置通过 `scripts/configure-admin-auth.mjs` 管理。不要把真实密钥写入源码。
4. 飞书自动化要分别授权应用访问目标多维表格、模板和文档文件夹，并配置对应字段。
5. 连接检查仅验证接口连接，不等于通过真实视频或商品端到端验收。

## 飞书机器人设置

1. 在飞书开放平台创建企业自建应用并启用机器人。
2. 在事件订阅中选择“使用长连接接收事件”，添加接收消息事件。
3. 添加卡片交互回传，让报告卡片上的标签和重新分析按钮生效。
4. 按网页设置页的清单开通消息、群信息、用户基本信息、文档、云空间、素材和协作者权限。
5. 发布应用，把机器人加入需要使用的群聊。
6. 回到本工具设置页填写 App ID 和 App Secret，启用后点击测试连接。

## 飞书多维表格自动化

云端接口：`/api/feishu/automation`。在飞书自动化中使用“发送 HTTP 请求”，方法选择 `POST`，请求体至少传入：

```json
{
  "appToken": "多维表格 App Token",
  "tableId": "数据表 ID",
  "recordId": "触发记录 ID",
  "secret": "自动化接口密钥",
  "fields": {
    "PID": "1732507663809155965",
    "产品名称": "产品中文名"
  }
}
```

PID 必须是文本型完整数字，不从商品链接的英文名称推断商品。产品名称可省略；省略时先从同 PID 缓存或数据源读取名称，失败则提示人工补填，不创建随意命名的文档。详见 [名称可选](deploy/HANDCARD_OPTIONAL_NAME.md)。

只有按钮触发创建或关联手卡。按照配置文件夹中完整的 `_PID` 标题后缀查找，多个匹配时选最近编辑的一份，并规范名称为 `产品名称_PID`。同一行的按钮任务串行处理，同 PID 创建在当前进程中串行。先回填手卡链接，再整理资料；已有缓存尽量复用，不是每次点击重新请求收费数据源。

普通“补录手卡”只补空白基础字段；已有文字（包括“未找到”“暂无”）保留。六项基础字段都已有内容时，不再为补录调用商品整理模型。要替换已有内容，进入后台 `/admin/products`（产品与手卡），在对应的关联手卡链接下点击“刷新基础资料”并确认。刷新只用已有整理缓存改这份手卡的六项基础资料，不调用出海匠或模型，不改视频、翻译或其他区块；缓存没有支持的事实仍保留原文。需要重新运行模型时，另用该页面带费用确认的“重新整理”操作。

上述四个飞书入口支持请求头 `X-Idempotency-Key` 或请求体 `requestId` / `request_id`。一次触发的网络重发必须携带同一个编号；主动重试/再次点击必须换新编号。编号不能固定写死，也不能只用 PID、记录 ID 或视频链接代替。旧自动化不传编号仍能调用并保存任务，但响应标记 `deduplication: "request_id_missing"`，**不会自动获得防网络重发保护**。本轮未修改线上自动化来接入编号，同链接在不同手卡仍独立处理。

四个入口在返回成功之前，将接收记录和加密输入一起提交到 MySQL。回调只负责唤醒，后台每 10 秒检查本地接收任务；该检查不是扫描飞书。视频任务与目标行绑定在同一事务中创建。未开始的任务可以恢复；已经开始后中断、无法证明外部调用结果的手卡或视频暂停待核查，不自动重做收费请求。旧机器人、文档扫描、兼容字幕入口尚未统一进入这个接收箱。

`lib/video-execution.ts` 通过 MySQL 会话锁限制同一数据库上的新版视频工作进程合计最多执行两个视频，并保护同一视频任务不被同时领取。旧版程序不遵守新锁协议，因此不能混跑；PID 创建与飞书文档/行写入锁尚未全部跨进程化，暂不据此增加应用副本。

商品资料优先读取 TikTok 公开同 PID 页面并保留普通文本描述；模型仅分析商品描述区域最多 8 张详情图，不分析主图和 SKU 图。主图仍可作为基础元数据展示。公开源被验证码等拦截时会明确失败；只有显式启用 `CHUHAIJIANG_FALLBACK_ENABLED` 才允许出海匠付费备选。模型可在后台按商品、视频、翻译用途配置，商品默认 Qwen，不强制使用 OpenAI。详见 [商品缓存](deploy/PRODUCT_CATALOG.md) 与 [页面结构恢复](deploy/PDP_SCHEMA_RECOVERY.md)。

视频处理单独使用 `/api/feishu/task-table`，或飞书应用动作 `/api/feishu/app-actions/video`；手卡应用动作是 `/api/feishu/app-actions/handcard`。任务表视频使用 `transcript_only` 模式：返回文件、TokScript 原口播、中文翻译及配置的字幕，不调用完整视频分析。手卡文档沿用 `product_doc` 作为任务归属标记，但只下载视频文件、提取口播和翻译，不再识别镜头或调用视频分析模型；视频文件仍保留原音轨。手卡“视频分析”列完全由用户维护：不自动填入结果、错误或占位文字，不清空历史内容，也不再通过清空该格触发重试。中文翻译独立取自 TokScript 或文本翻译请求，已有非空翻译保留；视频文件继续写入原“分析状态/视频文件”格。商品基础资料分析及其他完整视频分析入口不变。旧的手卡分析报告、配置和数据库字段仅兼容保留，不自动补写或重跑；后台不再提供手卡视频分析提示词及历史输入重放。

手卡发现流程每 20 秒批量读取全部已登记手卡的修改时间（每批 200 份），只对改动、未交付或需复核的手卡检查版本和链接；数据库目标清单使用一条轻量查询，不再每轮逐产品查映射。冷启动检查有界并发 4，最近修改的手卡优先，后台检查队列不会阻塞下一轮修改时间发现；启动后仍不立即扫描。文件上传与链接发现分开，翻译不等待文件上传；任务完成按绑定文档投递，并合并同一任务的重复回填通知。已存在的视频预览不重复验证或上传，手卡不额外下载封面。原有两个视频任务并发、超时、下载兜底和原音轨校验保留。20 秒为正常网络下的发现周期，不是下载、翻译及飞书附件处理的完成时限；元数据失败会退回版本检查，同秒编辑及定期版本复核用于防止漏检。

文档读取按凭证和接口分别限制为每 500ms 启动一次，为其他操作留出余量；限流时共享冷却间隔，安全读取最多请求两次，排队和冷却均受原请求超时及取消约束。写入、上传、视频和模型请求不在此处自动重试。版本读取或批量元数据被限流时不会转成整份文档或数百次逐卡读取；其他读取故障保留原有回退。持续不可读的手卡按 20 秒（元数据不可用时 60 秒）逐步退避，最多 5 分钟；新修改或归属变化可立即重新检查。

字段名不同可配置 `fieldMap`，值为 `""` 表示明确停用。视频写回只补空白，保留人工文字和已有附件；写回前重新检查行的链接是否仍属于当前任务。完成结果另行定点写回，不依赖下一轮扫描。

任务链路的 TokScript 口播与下载工具独立调用，一项失败不丢弃另一项。下载、口播、翻译、视频分析各自记录状态，后台 `/admin/tasks` 展示分环节结果及未完成的表格回填。翻译缺失保持空白，不用“暂无中文翻译”占住单元格；翻译仍在进行时不会被提前暂停。明确无权限的写回暂停；暂时性写回失败依次等待 30 秒、1 分钟、5 分钟、15 分钟、1 小时，连续第 6 轮失败后暂停。这里限制的是写回轮次，不是付费模型请求数。仅重试翻译/下载/回填的独立按钮仍待实现，现有“重试”是整项任务的新执行。

表格任务的分段字幕按视频任务及本次执行持久记录模型请求预算：最多两次实际请求，模型内部重试也计入；成功翻译缓存后，上传重试不再重新翻译。失败只暂停字幕回填，不撤销视频、原口播、中文翻译等其他成功结果。旧 `/feishu/*subtitle` 兼容入口尚未统一接入持久预算，不应把它们的重复 HTTP 提交视为已受同一任务预算保护。

生产环境必须设置 `FEISHU_AUTOMATION_WEBHOOK_SECRET`，不要把接口裸露给公网。

旧 `POST /api/products/parse-public` 已退役：通过原有鉴权后固定返回 HTTP 410 和 `PRODUCT_LINK_ANALYSIS_RETIRED`，不读取请求体、不抓页面、不调用模型；`debug: "capture"` 也不再提供。此修改部署后生效。历史解析实现和测试保留供追溯，不被当前应用入口引用，不应重新接入。飞书按钮的 PID 资料流程、缓存和视频处理不变。

只有在仍使用的模型功能中选择 OpenAI 时才需要相应 OpenAI 配置；这次停用旧入口不删除共享密钥或历史数据。服务商密钥保存在数据库加密字段或部署环境；说明文档只记录配置位置，不记录值。

后台使用 `.data/admin-auth.json` 内的加盐密码散列鉴权，并要求生产 HTTPS。飞书自动化保留独立鉴权。`/api/health` 只证明 HTTP 服务在线，数据库与配置完整性需要另跑 `deploy/check-runtime.cjs`。

应用部署在服务器；本机关闭不影响云端运行。应用的文档和表格访问权限仍须由飞书管理员配置。

### 优质视频库复用通用视频处理

根据负责人 2026-10-21 的要求，删除专用 `/api/feishu/video-library` 入口、执行器、服务商适配器和配置脚本，不再维护独立五槽任务链。《优质视频库》改用现有 `POST /api/feishu/task-table`，与其他任务表共用接收箱、视频队列、TokScript、翻译和附件回填。手卡完整视频分析不变。

目标 Base 为 `GujZbD0psaRxBrs6WSJc5d6anud`，表为 `tblgmuFeWjhWXfRd`。既有飞书原生流程分别响应新增记录和仅视频链接修改，HTTP 表单发送 `appToken`、`tableId`、`recordId`、`视频链接`、`credentialSource=chatgpt`，请求头仍用现有 `X-Feishu-Automation-Secret`。本表原应用有读取但无写入权限，因此选择已经获本表授权的 chatgpt 应用；默认不传该参数的其他表仍用原应用。chatgpt 选择要求表格已有保存的字段配置，且实际读写仍由飞书权限决定。不再传递已删除的系统时间或依赖处理状态列；原经典「自动化流程」继续停用，防止重复调用。

按现有 `feishu_field_mappings` 保存本表映射：`videoUrl=视频链接`、`videoFile=文件`、`transcript=原口播`、`translation=中文翻译`，其余映射显式设为空字符串。这样不生成字幕、手卡或视频分析，也不向不存在的列写入。`日期`、`产品名称`及已有文字和附件不被覆盖。沿用通用任务表原有的重试、两槽视频并发和后台错误记录；TokScript 没有提供中文时，沿用已配置的 Qwen 文本翻译。启用配置不会提交历史链接；只有新的飞书触发请求进入队列。

其他表可继续使用同一接口并分别保存字段映射，不需要再复制业务程序。飞书应用必须有对应表格的实际读写权限；字段相同不等于自动取得授权。Webhook 不带稳定 `requestId` 时仍沿用旧入口兼容行为，不宣称能够识别所有外部重复投递。

## 数据位置

- 结构化数据：MySQL，连接由 `MYSQL_*` 配置，生产使用独立命名数据卷
- 原视频及衍生文件：`.data/media/`
- 商品原始资料与模型证据：`.data` 内的商品缓存，具体路径由 `catalogDirectory` 管理
- 已生成的分段字幕翻译缓存及请求预算标记：`.data/subtitle-cache/`
- 飞书接收：MySQL `feishu_request_receipts` 保存哈希及状态，`feishu_inbox_tasks` 保存加密输入、处理状态及关联视频；解密依赖原 `.data/secret.key`
- 视频分环节结果：MySQL `video_stage_results`；表格写回暂停与退避分别在 `feishu_automation_delivery_blocks` 和 `feishu_automation_delivery_retries`
- 已退役优质视频库专用链路：既有 `feishu_video_library_rows`、`feishu_video_library_tasks`、`.data/media/video-library/` 和旧配置只保留作历史资料，不删除生产缓存或原片；新安装不再建这两张表，运行和就绪检查也不再依赖它们。本表新任务使用上述通用任务数据位置
- 本机加密主密钥：`.data/secret.key`
- 后台登录散列：`.data/admin-auth.json`

MySQL 与 `.data` 是两份不同的数据。迁移时都必须保留；丢失 `secret.key` 后无法解密已保存的 API Key。本轮审计没有执行备份或删除生产数据。

## 开发检查

```bash
pnpm run check
pnpm test                 # 现用功能及旧入口关闭保护；需要隔离 MySQL
pnpm run build
pnpm run test:legacy      # 退役商品链接分析的历史测试；保留已知失败
pnpm run test:all         # 现用和历史测试合并运行；不等于日常发布验收
```

数据库用例使用隔离 MySQL，禁止指向生产库。CI 通过 `deploy/smoke-test.sh` 启动专用临时数据库；本机只允许校验过路径与归属的临时 socket。没有隔离环境时明确失败，不会回退使用生产 `MYSQL_*`。

`tests/` 顶层是现用测试，两个发布工作流加隔离 smoke test 必须覆盖其中每个文件；新增文件漏配会使边界检查失败。退役入口的原断言移至 [历史测试说明](tests/legacy/README.md)，已知 31 项失败没有修复或隐藏。`pnpm test` 通过只代表现用测试集合通过，不等于 `test:all` 或生产端到端已通过。

生产由 `main` 分支工作流部署；不要为运行测试而推送 `main`。隔离验收工作流使用 `codex/verify-handcard-*` 分支，不包含生产凭证。
