# 补录手卡支持仅填写 PID

## 行为

- 产品名称改为选填，PID 仍为必填的完整文本编号。
- 请求中没有名称时，入口仍先读取当前行已有的名称；有人工名称时优先使用，不额外查询名称。
- 当前行也没有名称时，只从该 PID 经校验的出海匠原始资料中读取 `product_name`，其次读取 `product_title`。不按链接、相似商品、其他字段或模型生成名称。
- 没有缓存且该 PID 从未取数时，复用现有数据库占位与持久化请求标记，最多执行原有的一次商品详情请求。后续商品资料整理使用同份缓存，不再次取数。
- 已请求但结果不确定、失败或缓存损坏时，不自动重新收费取数；接口没有名称时提示人工补填。
- 获取名称本身不调用 AI。获取名称后，手卡资料整理仍按原有模型配置执行。
- 文档仍按 `产品名称_PID` 命名，按 PID 查找复用。供应商名称即使包含“测试”，也不会触发人工测试专用的强制新建逻辑。
- 不新增回写产品名称列的行为；表格结果仍回写手卡链接和手卡状态。

## 自动化配置

请求地址、密钥、appToken、tableId、recordId、PID 和输出字段不变。
现有流程无需修改，产品名称列可以留空。如果表里没有产品名称列，可以移除请求体的产品名称项目，并在完整 fieldMap 中设置 `"productName":""`，保留其他配置。

名称已填写时仍先回填手卡链接再整理资料。只有 PID 时，需要先取得供应商名称才能创建或重命名文档，因此首次返回手卡链接可能稍慢。商品详情查询失败时不会创建无真实名称的占位文档。

本文件描述待发布改动，不表示已经部署。原 Word 教程是先前线上版本的快照，部署本次改动后产品名称必填的说明以本文件为准。

离线测试应覆盖：人工名称优先、PID-only、原始名称缺失、PID 错误、缓存损坏、查询失败、并发与重启不重复取数、AI 失败不影响缓存名称读取，以及供应商名称含“测试”仍复用手卡。

生产发布前只提交本次相关文件，勿混入工作区里其他未完成改动。发布后在授权的验收行先用已缓存 PID 留空名称点击一次，核对手卡命名、复用及回填；再经确认用未缓存 PID 验证唯一一次收费查询。不得删除生产缓存或请求标记来重试。
