| 通知异常 | 异步通知拒绝未被同步 try/catch 捕获 | 捕获异步拒绝；提示通知失败不打断视频任务；运行中任务不再从旧卡片重复启动 |
| 机器人队列阻塞 | 发不出“处理中”卡片时，已创建的视频未入队 | 提示卡发送/更新失败不再阻止入队；保留独立报告投递，并只记录脱敏诊断 |
| 媒体下载 | 只看 Content-Length，分块响应可绕过大小限制；失败时可能损坏旧文件 | 流式计数：视频 600 MB、封面 12 MB；先写临时文件，成功后替换，失败清理临时文件并保留旧文件；拒绝空下载 |

| 视频 Range | 倒序、越界或后缀请求处理不准确 | 严格处理单区间、后缀及开放结尾请求，异常返回 416；不把目录当媒体文件 |

| 扫描参数 | 非数字配置可能导致异常轮询节奏或无扫描 | 有限数校验、批大小取整与安全边界 |
| 提示词调试 | 翻译调试界面显示新草稿，实际请求却使用旧保存模板 | 调试请求使用当前草稿；普通任务仍用已保存模板 |

| CI 覆盖遗漏 | 仍使用的文档迁移与两个文档入口测试未加入 CI，部署分支也未运行工作流保护检查 | 两个发布路径补齐；新增检查要求现用测试文件全部被工作流或隔离 smoke test 执行，测试容器只用离线或隔离数据库网络 |

## 3. 线上只读快照与扫描差距

本次查询观察到：

- 产品档案及映射表合计去重后有 **382 个手卡文档 ID**；不代表这 382 份当前都能被应用读取。
- 当时没有正在运行的视频分析任务。
- 有 **39 条已暂停的表格回填任务**：33 条记录不存在、5 条字段不存在、1 条源链接变化。
- 其中历史最高尝试数为 4082，但这些任务当前都有持久化暂停标记，**不是仍在不断重试的 39 个任务**。本轮没有恢复、删除或清空它们。
- 当时商品缓存中没有处于 `requested` 的取数不确定项。
- 线上扫描间隔为 20 秒、每批 12 份；当前为一个应用容器，不是多副本。

**代码事实：**每轮重新列出产品及文档映射，只扫描一批，文档之间串行；上一轮未完成时跳过下一次定时触发。以 382 份全部参与扫描估算：`ceil(382 / 12) × 20 秒 = 10 分 40 秒`，另加外部 API 耗时及跳过轮次的影响。这是覆盖周期估算，不是现场测得的最坏延迟。

**负责人要求：**每份手卡尽量在 20 秒内发现新链接。当前实现没有满足这一要求；“定时器设为 20 秒”不能作为已经满足的证据。

**建议：**优先验证飞书能否把变更文档/行定点通知本应用，按通知立即处理，低频全量轮询负责查漏。如果手卡正文没有可用的变更事件，再评估手动触发入口或活跃文档优先队列。没有验证事件能力和权限前，不承诺 20 秒，也不擅自提高全量扫描频率制造大量请求。

## 4. 已确认的需求边界与当前实现

| 要求来源 | 当前代码事实 | 判断 |
| --- | --- | --- |
| 同时处理两个视频；每个任务独立停止和超时 | `lib/queue.ts` 本地限 2 个，`lib/video-execution.ts` 另持有同库共享的两个执行槽位及单任务锁；30 分钟上限及执行归属保护保留 | 本地真实 MySQL 8.0.46 多连接锁争用及槽位上限通过；断连故障注入仍使用 mock；不覆盖未升级的旧进程，也不等于飞书写入已支持多副本 |
| 同一视频在不同手卡仍重新分析 | 不按 URL 全局唯一；本轮字幕缓存也按任务/执行次数分开 | 保留该要求，不能用全局 URL 去重解决重复通知 |
| 同一次自动化网络重发不重复执行，主动提交仍可新建 | 四个入口新增基于操作编号的持久接收记录 | 后台本地实现；现有飞书发送方尚未接入编号，不能声称线上已去重 |
| Qwen 单次最多 600 秒、最多请求两次 | 完整视频请求 600 秒；配置重试为 0/1；本轮未扩大 | 不等于字幕、写回、TokScript 各环节合计只有两次 |
| 完整视频要含画面和原音轨 | 本地 MP4 音视频检查后发送完整 MP4，不以口播文本替代该输入 | 本地协议及音轨回归通过；未在本轮收费验证具体模型确实理解声音 |
| 视频分析失败不应影响中文翻译 | 原口播翻译有独立异步路径；本轮增加独立失败状态和后台展示，等待中的译文不提前暂停 | 已有结果可单独写回；只重试翻译的持久任务与按钮仍未完成 |
| 表格人工视频分析/中文翻译不覆盖 | 视频回填只补空并重读源链接 | 保留；人工恰好在读写间隙修改的极小窗口仍不是原子条件写入 |
| PID 是商品唯一依据，产品名可省略 | 文本 PID 校验、同 PID 查找/缓存、名字缺失时从资料补名称 | 保留；数字型长 PID 精度已丢失时拒绝猜测 |
| 商品资料只分析描述详情图，最多 8 张，不分析主图/SKU 图 | 当前 catalog 提示及证据路径遵守该视觉限制，普通描述文本仍参与分析 | 主图可作为元数据显示；SKU 文字仍是资料来源，不等于分析 SKU 图片 |
| 每 PID 付费取数不应反复收费；暂不启用付费备选 | 原始缓存、请求标记、失败分类；付费备选须显式配置 | 本轮未启用出海匠，未调用收费接口；模型整理和商品取数必须分开计费统计 |
| 手卡只由按钮创建，不由视频完成自动生成 | 普通创建入口保留按钮方式 | 本轮没有新增自动化或改变已有飞书工作流 |

## 5. 仍需工程处理的风险

### P1 接收箱已覆盖四个入口 其余链路和不确定结果仍待完善

`app/api/feishu/{automation,task-table,app-actions/handcard,app-actions/video}/route.ts` 已在应答前原子保存接收记录与加密输入，`after()` 仅唤醒后台。`lib/feishu/inbox.ts` 启动及每 10 秒读取本地接收表，两种任务分别领取；视频与目标行一起提交，周期性唤醒只处理这些已绑定的视频和已知的延后任务，不抢跑旧流程尚未绑行的新视频。

未开始的任务可恢复；已开始的手卡或视频发生进程中断时保守暂停，避免外部请求已产生结果却又自动重跑收费。后台 `/admin/tasks` 显示接收中断、分环节状态、回填暂停原因。加密依赖持久 `.data/secret.key`；旧接收记录若没有保存输入，不能凭哈希重建。

机器人、文档扫描及兼容字幕服务尚未统一使用这个接收箱；旧混合手卡/视频入口内部的后续步骤也不等同于新视频入口的单事务绑定。付费结果核查后只恢复指定阶段的工作尚未完成，不能声称整个应用都能无损自动续跑。

发送方必须提供稳定的 `X-Idempotency-Key` 或 `requestId` / `request_id`；一个触发实例的重发沿用编号，主动新操作换新编号。同编号不同内容返回 409，格式错误返回 400。旧自动化未传编号仍可用并返回 `deduplication: "request_id_missing"`，当前未修改任何线上自动化，不自动以 URL、PID、记录 ID 或时间窗代替操作编号。

### P1 分环节结果已保存 但独立重试还未完成

任务链路使用 TokScript 的部分成功模式，下载与口播工具并行；不再因口播工具失败丢弃下载结果。四项阶段结果保存在 `video_stage_results`，迟到的旧执行不能更改新执行阶段，失败不能抹掉同阶段已经确认的成功。缺失不是“无口播”，也没有新增对下载文件做 ASR 的兜底。

仍需实现“仅重试翻译”“仅重试下载”“仅重试写回”的持久任务和确认入口。目前后台“重试”仍是整项新执行，不能当成免费回填。TokScript 连接、列工具或短链接解析失败仍可能先中断获取流程，尚未覆盖所有前置失败的下载兜底；旧字幕兼容入口仍采用原串行契约。

### P1 视频领取已有共享锁 PID 创建和飞书写入尚未跨进程化

新视频工作进程以数据库命名空间隔离 MySQL 会话锁，合计两个执行槽位且同视频只能一个拥有者；连接失效时取消本次执行，不能将未确认释放的连接放回连接池。锁不随事务提交释放、会话断开会释放，因此恢复逻辑还必须检查已开始的持久任务，不能只看锁是否空闲。[MySQL 官方锁函数说明](https://dev.mysql.com/doc/refman/8.0/en/locking-functions.html)

PID 创建、文档锁和行锁仍有进程内实现。增加副本前还要统一写入锁及唯一约束，并验证真实数据库并发；不能因为视频领取已保护就扩为多副本。未升级的旧代码不遵守新锁协议，不支持新旧工作进程混跑；也不保证外部服务立即停止一个已经收到的请求。

### P1：任务字幕预算已收口，其他长期回填与兼容入口风险仍在

- 根据负责人本轮确认，表格视频任务的字幕最多两次实际模型请求。调用前按视频任务/执行次数排他创建请求标记；模型内部重试也计入。进程重启或分段内容变化不重置该预算；成功结果另按分段缓存。新的主动分析任务有独立预算。
- 字幕两轮未完成时暂停字幕回填；已成功的视频、口播、中文翻译保留。媒体文件尚未交付时，仍允许独立交付文件，不能因字幕失败把它一起停掉。写回重试不重新翻译已缓存字幕。
- 行不存在、字段不存在、源变化和明确权限拒绝已暂停；暂时性错误按 30 秒、1 分钟、5 分钟、15 分钟、1 小时持久退避，连续第 6 轮失败暂停。该预算不是模型收费次数，单轮普通写回仍可作最多 3 次短重试，429 不立即重复。等待中的独立翻译在 30 分钟范围内保留等待状态，不提前永久暂停。
- 旧 `/feishu/*subtitle` 兼容入口未统一接入持久化调用去重和跨提交预算，客户端重复 HTTP 请求仍可能重复翻译；不能把任务链路的新上限外推到所有旧入口。

付费请求预算与写回次数已分开；恢复权限后直接续写的专用入口仍待补齐，现有整项主动重试会开始新的执行，不能推荐为零费用恢复。字幕准备轮次还与写回尝试计数有关，需要进一步拆出字幕独立调度。网络超时不等于供应商一定没有处理，仍须保留不确定结果。

### P1：全量测试尚不能作为发布保证

旧 SQLite 数据库测试已迁移到隔离 MySQL，当前登录、PID 缓存与飞书按钮行为的过时断言已更新。停用前最近一次全量运行仍有 31 项旧分析器测试失败：一部分是整次拒绝的旧预期，一部分确实暴露了证据校验漏洞，不能全部归为测试过时。

负责人随后决定停用旧入口。本分支的 `/api/products/parse-public` 不再加载旧解析器，普通和调试请求都固定返回 410；新增回归检查 `app/` 与 `lib/` 中的活动模块不会导入或重新导出这两个历史解析模块。该处理隔离了旧 HTTP 入口，不等于修好了历史模块。

原安全测试已原样归档到 `tests/legacy/`，仅调整源码相对路径；混在应用测试中的 43 条历史解析器断言也拆出，现用断言保留。`pnpm test` 执行全部现用测试，`test:legacy` 单独执行历史测试，`test:all` 包含两者。已核对归档前后断言一致，没有删除失败断言或增加跳过。现用集合通过不代表包含历史模块的全库通过，也不允许未经重新审查恢复旧模块。归档范围与已知 31 项失败见 [历史测试说明](../tests/legacy/README.md)。

### P2：媒体链接是“拿到链接即可访问”

`lib/admin-auth.ts` 将媒体 GET/HEAD 和商品图片 GET/HEAD 放在公开机器路由，支持飞书和模型读取。后台有密码不等于这些媒体 URL 私有。改成登录或签名链接可能影响历史飞书播放，需要明确业务选择和迁移策略；本轮未调整权限策略。

### P2：应用动作 token 的轮换兼容性尚未验证

`lib/feishu/chatgpt-app.ts` 获取该应用当前 tenant token，再与动作请求所带 token 比较。本轮补了超时和完整凭证指纹，但没有验证新旧 token 有效期重叠、轮换时序及每次请求取 token 的额外开销。需要结合实际飞书动作认证约定验收，不能简单缓存旧 token 或取消检查。

### P2：历史实现和存储长期增长

- 普通手卡入口、独立补资料、旧商品解析器、兼容字幕服务及历史网页存在相近能力；保留不代表每条路径已验证一致。未据文件名判断“废弃”并删除。
- README 已更新，旧需求确认文档仍保留。后续应标明入口、业务状态及对应测试，逐步合并实现，不做一次性大重写。
- `.data`、媒体、商品原始证据及本轮新增字幕缓存会随长期保留增长。按已有永久保留要求，本轮没有自动清理；需要容量监测和可选归档策略。
- 批量上传虽然先做输入检查，磁盘中途失败仍可能留下部分已建记录；需要批次状态/补偿，而不是自动删除用户记录。
- TokScript 长链接直接返回、短链接恢复账号信息采用页面字段，仍需不同链接形态的真实样本验证，不能保证所有页面变体可解析。

### P2：资料质量与模型能力不能只靠 schema 证明

catalog 校验会检查 PID、字段、来源编号和缺失标记，但一个有效引用编号不自动证明模型对图片尺寸、宣传用语或商品语义理解正确。当前普通字段“尽量 120 字”主要由提示词约束，代码的总长度上限更宽；严格裁剪可能损失资料，未擅自改需求。

后台对完整音视频能力的确认是人工配置，不是对任意新模型的声音能力检测。更换模型后需要用户同意的真实有声/无声样本验收；本轮未额外付费测试。
